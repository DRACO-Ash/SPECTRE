## Notes

Systemic observations.

● **Username-keyed, lifecycle-blind session store is the spine of the worst findings.** F-S07-01, F-S08-02, F-S08-03 and F-S08-11 all stem from one design: `planning_state._store` keyed by username with no binding to the account's identity or lifecycle, plus session tokens that carry only `{sub, gen}` and a generation counter that resets to 0 on recreation. Delete+recreate (executed) turns an old operator token into the new account's role (F-S08-02) and hands over the previous holder's live UDL credentials (F-S08-03). F-S07-01/F-S08-03 are facets of the same root; I kept them separate because the reviewer split credential-lifetime from the delete path and the fixes differ (key by user-id/nonce vs clear on delete). Not marked hard duplicates.

● **NOTSO cache is broken end-to-end against the real data shape** (F-S07-03, executed): the committed 500 records use `id`/`msgBody`/`msgBody.SatIds` and none of `msgId`/`satNo`/`msgText`, so dedup never fires and `get_for_satno` always returns []. This compounds F-S07-04 (uncapped sync loop) and F-S07-13 (non-atomic whole-file rewrite). F-S07-05 (committed marked REAL data) sits on the same file.

● **UDL egress has no per-route rate-limit discipline** (F-S07-02, F-S07-08, F-S07-19): several authed routes reach UDL/third parties with no limiter, and /pol/analyse is a credential oracle around the /udl/login limiter.

● **One genuine refutation and three downgrades** (honesty check): F-S08-04 REFUTED by execution — Starlette 1.6.0 `request.url.path` strips newlines, so the audit-log-forging exploit cannot fire (the missing `log_safe` is harmless hygiene). Downgrades: F-S07-04 High→Medium (infinite loop is UDL-paging-dependent, unproven), F-S07-09 High→Medium (wrong-TLE impact depends on UDL default ordering, and the STALE badge mitigates), F-S07-12 Medium→Low (autoescape bypass real but no attacker-controlled error text today).

● **Repository and clone untouched.** All execution ran against the scratch clone with a temporary SPECTRE_DATA_DIR/SPECTRE_SQLITE_DIR under refute/work/ and SPECTRE_COOKIE_SECURE=false; `git status --porcelain` on the clone is clean. bcrypt 5.0.0 behaviour (>72 bytes → ValueError) confirmed by execution.
