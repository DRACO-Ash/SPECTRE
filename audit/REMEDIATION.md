# SPECTRE audit: remediation plan (phase 8.2 and 8.3)

One row per confirmed finding (296). Fix and Gate come from the finding (`audit/FINDINGS.md`). Every row carries a regression gate: the test, lint rule, type constraint or CI check that would fail if the defect returned.

**Effort and blast radius are estimates (inference), derived mechanically:**
● S: one location in one file.
● M: two files, or several locations in one.
● L: three or more files, more than four locations, or a design, structure or complexity lens.
Blast radius counts the distinct files cited and the areas they sit in. Treat both as a sizing aid, not a commitment.

## Sequence

1. **Blockers first**, before the console is used for any decision. Each is either an exploitable security flaw or a numerically incorrect output presented as computed.
2. **Unblock the gates.** Make CI execute (F-S00-01 and F-S00-08 together), so every later fix lands behind real lint, type and test jobs. This is the cheapest high-value change in the repository.
3. **Quick wins:** High and Medium findings with a single-location fix (effort S).
4. **Structural:** everything else, grouped by the root-cause clusters below so one change closes several findings.
