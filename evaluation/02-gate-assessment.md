# 02. Gate assessment, G1 to G10

**Subject:** commit `ddba577`. **Yardstick:** framework section 5.2. **Assessor:** one. The assessor also built much of this code earlier in the same session, which a Technical Director should weigh (section 4).

## 1. Rating rule as applied

The framework defines Green (met with objective evidence), Amber (substantially met with a dated, owned remediation plan) and Red (not met or no evidence). It does not define "substantially met, but no dated, owned plan". The repository holds no dated, owned plan: `.board/items.json` names backlog items and `.board/PLAN.md` orders them into releases, but neither carries a date or an owner per item (`.board/config.json` names one person and no dates). Such gates are therefore rated **Red** and labelled "Red (substantially met; Amber once a dated, owned plan exists)", so the distance to Amber is visible. This is a deviation recorded in the report.

Ratings here rest on code reading. Gates G2, G6, G7 and G10 are re-checked by the Phase 4 probes named against them, and this file is revised if a probe contradicts a rating.

## 4. Independence

The assessor in this session also built or directed most of the engine code assessed here, under the owner's instructions. The evidence rule (every rating cites code, a command or a probe) is the control against that; it does not replace a second, independent assessor, which section 5.5 of the framework requires and which this evaluation recommends.
